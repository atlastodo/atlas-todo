# AGENTS.md

## Working with the user (standing instruction)

- Before planning work on a bug, ask questions until the bug is properly understood (symptoms, reproduction, expected vs actual).
- Also ask questions about the proposed solution before implementing — don't assume intent.

## This repository

- The Atlas Todo **app**: `apps/mobile` (React Native + Expo, the one UI for Android, iOS and the web) and `apps/electron` (the Linux desktop shell around the web export). Its history was filtered out of the former monorepo, which is now the **core** repository, `atlastodo/atlas`: the sync server (Rust + Postgres), `manifests/`, `test-vectors/`, the core JS packages (`@atlastodo/client-core`, `@atlastodo/shared`, `@atlastodo/sdk`), the `atlas` CLI, the Docker image, the NixOS server module (`services.atlas-todo`) and the server, architecture, sync-protocol and integration docs. Server, protocol, crypto, i18n catalog and task-rule changes start there.
- The core packages come from **npm** at an exact version: `@atlastodo/client-core` and `@atlastodo/shared` (now `0.1.11-rc.8`, the `next` dist-tag) in `apps/mobile/package.json`. Each package depends on its siblings at the same exact version, which npm resolves, so no `overrides` entry is needed. Keep both on one core version; upgrading core = change the two versions, `bun install`, `nix:bun-lock`, `test:all`, a web export, and move `ATLAS_SERVER_IMAGE`'s default in `devenv.nix` to the same core release. The apps import the packages' built ESM `dist/` (no `@atlastodo/source` condition here); jest transforms them (`@atlastodo` is in `transformIgnorePatterns`' allowlist) and tests read their shipped fixtures as `@atlastodo/client-core/test-vectors/*.json` (no vectors are copied into this repository). Dependabot ignores `@atlastodo/*`.
- The app's version line continues the monorepo's (the last monorepo release was v0.1.11-rc.5, Android versionCode 11105); the app no longer has to be in lockstep with core.

## Dev environment

- All dev commands (`web:dev`, `mobile:dev`, `desktop:dev`, `desktop:start`, `desktop:package`, `nix:bun-lock`, `test:all`, `lint`, `fmt`, `version:bump`, `screenshots`, `web:release-tarball`, `build:android:*`, `android:permissions`, …) are devenv scripts defined in `devenv.nix` — run them inside `devenv shell`. The root `package.json` has **no** scripts; there is no root npm/bun task runner. (The full-suite script is `test:all`, not `test`: a script named `test` collides with the shell builtin and `devenv shell test` silently no-ops.)
- Bun is the package manager (`bun.lock` committed; CI installs with `--frozen-lockfile`); Node 26 is the runtime (devenv, `engines`, CI). Bun is pinned to **1.4.2** everywhere — devenv (via the nixpkgs snapshot in `devenv.lock`) and `BUN_VERSION` in `.github/workflows/*.yml` and `.github/actions/android-setup` callers — bump them together.
- There is no server or Postgres here. `web:dev`, `desktop:dev` and `mobile:android` talk to `EXPO_PUBLIC_API_URL` (default `http://localhost:8080`): a server run from the core repo (`devenv up` + `cargo run -p atlas-server` there) or its image. They warn, and start anyway, when nothing answers. `screenshots` runs a throwaway Postgres and the core server image (`ATLAS_SERVER_IMAGE`, default `ghcr.io/atlastodo/atlas:0.1.11-rc.8`, the pinned core release; move it with the core pin) in Docker.
- The Android SDK is opt-in (several GB): a gitignored `devenv.local.nix` containing `{ android.enable = true; }`, then re-enter the shell. Only the local native scripts (`emulator:*`, `mobile:android`, `build:android:local`, `build:android:aab`, `bundle:android:release`) need it, and they say so when it is off. Expo Go (`mobile:dev`) and EAS cloud builds don't.

## Verification

- `test:all` = full suite, in order: vitest in `apps/electron` → jest in `apps/mobile`, under `set -euo pipefail` (the first failure stops it). Nothing needs Postgres. `apps/mobile/src/ui/TaskRow.rerender.test.tsx` is a known flake under load: rerun it alone before chasing it.
- `lint` = `tsc --noEmit` for `apps/mobile` and `apps/electron` + `eslint .` (flat config in `eslint.config.mjs`: typescript-eslint recommended + react-hooks) + `prettier --check .` (`.prettierrc.json`, `.prettierignore`) + `scripts/third-party-licenses.mjs --check` + the `nix/bun.nix` freshness check. `fmt` runs `prettier --write .`. CI's `Lint (TypeScript)` typechecks with `bun run --parallel --filter '*' typecheck`.
- Runners are per-package, deliberately separate (not `bun test`):
  - `apps/electron`: `cd apps/electron && bunx --bun vitest run src/foo.test.ts` (vitest under Bun's runtime, supported since Bun 1.4; `test:all` and CI do the same).
  - `apps/mobile`: jest-expo (`bun run test -- <pattern>`) — must run under real Node; under Bun's runtime it dies at load (`Attempted to assign to readonly property`).
- A change to anything the web build bundles is worth a web export (`cd apps/mobile && bunx expo export --platform web`); a native change, a release APK build (`.github/scripts/android-gradle.sh` from `apps/mobile/android` after `bunx expo prebuild --platform android --clean`) and `android:permissions`.

## Layout

- `apps/mobile` — the single UI (React Native + Expo); the web app is the same code via react-native-web. Dynamic `accent-*` colors resolve to CSS variables (`--accent-<shade>` hex and `--accent-<shade>-rgb` channels from `@atlastodo/shared`) supporting Tailwind opacity modifiers (e.g. `bg-accent-100/60`, `dark:bg-accent-950/70`). Metro watches the workspace root (Bun's store, `node_modules/.bun`, lives there).
- `apps/electron` — the desktop shell. Its updater (`src/updater.ts`, `DEFAULT_REPO = "atlastodo/atlas-todo"`) reads this repo's `releases/latest`, which must keep carrying `atlas-desktop-X.Y.Z.tar.gz` and `SHA256SUMS.txt`.
- The root flake builds `web-dist` and `atlas-desktop` from source (derivations in `nix/packages/`, also exposed as `overlays.default`), along with `nixosModules` and `homeManagerModules` (`programs.atlas-desktop`; `default` = desktop). It re-exports nothing of the server: server users take `github:atlastodo/atlas`. The JS builds read npm dependencies (the core tarballs included) from `nix/bun.nix`, generated from `bun.lock` by bun2nix: run `nix:bun-lock` after every `bun.lock` change (`lint` fails when it is stale). `nix flake check` builds both and evaluates the Home Manager module. `packages.<system>.web-dist` is what a `services.atlas-todo.staticDir` points at. The release desktop tarball embeds its own flake (`nix/flake.desktop.nix` + `nix/flake.desktop.lock`, refresh with `desktop:flake-update`).
- `docs/android-permissions.md` is the allowlist of Android permissions: its "Declared" table is parsed by `apps/mobile/scripts/check-android-permissions.mjs`, which `release.yml` runs on the merged release manifest (locally: `android:permissions` after a release build) and which fails on any permission not listed, or listed but no longer declared. Unused permissions that dependencies add go in `android.blockedPermissions` in `app.json`.
- `docs/screenshots/` is the README's images, regenerated by `screenshots` (`scripts/screenshots.mjs` seeds a demo account through the web UI on a throwaway server and database, moving the browser clock for the habit and stats history).
- `site/` is the atlastodo.dev landing page and the Play listing's privacy and account-deletion pages.
- `dist-desktop/`, `dist-web/`, root `atlas-desktop-*.tar.gz` and `atlas-todo-web-*.tar.gz` are gitignored build artifacts — don't edit or commit them.
- Links: app releases, issues and discussions are `atlastodo/atlas-todo`; server, self-hosting, architecture, threat model, roadmap and decisions are `atlastodo/atlas`. Builds link the About screen to `EXPO_PUBLIC_REPO_URL` (the workflows set it from `github.repository`; `scripts/web-release-tarball.sh` defaults it to `https://github.com/atlastodo/atlas-todo`).

## CI & release (GitHub Actions)

- CI is `.github/workflows/`. Default branch is `main`; pre-releases are cut on the long-lived `dev` branch (see below). Commit messages follow Conventional Commits (`feat:`, `fix(mobile):`, …). A commit that fixes an issue puts `Fixes #N` (one line per issue) in its body: PRs target `dev`, where GitHub ignores closing keywords, so the keyword must travel with the commit and closes the issue when it reaches `main` with the next stable release. Don't rely on the PR description for this. `pr-base.yml` fails a PR into `main` that is not from `dev` (or a Dependabot security update).
- `ci.yml` runs on push to `main` and `dev`, on PRs, and when `release.yml` calls it. Jobs (check names): `Lint (TypeScript)`, `Test (TypeScript)` (vitest in apps/electron), `Test (mobile)`, `Audit (JS)` (`bun audit`). A `changes` job picks the jobs by changed paths; the audit runs when manifests or the lockfile change and weekly (Monday cron); a tag, a manual run or a release runs everything. A newer push cancels the running one. Branch pushes whose head commit starts with `chore(release):` skip CI; the tag run tests that commit.
- The release's Android build reads caches (Gradle, NDK/CMake, ccache: `.github/actions/android-setup`, shared flags in `.github/scripts/android-gradle.sh`) that only `android-cache.yml` writes, on `main` (push, weekly, manual): a tag run can't read caches another tag saved. Keep the two builds' flags and env identical, or the caches miss.
- Release pipelines of two tags running at once race at the Play upload: the lower `versionCode` is refused once the higher one is on the track.
- Dependabot (`.github/dependabot.yml`): weekly version updates for Actions and Bun, grouped minor/patch, targeting `dev`. Security updates are on as a repo setting and always target `main`: merge one there, then merge `main` back into `dev`. Dependabot doesn't update `nix/bun.nix`; `dependabot-bun-nix.yml` regenerates it on its bun PRs and pushes to the PR branch.
- `scripts/third-party-licenses.mjs`: `--check` (in `lint` and `Lint (TypeScript)`) fails when a shipped JS package (the `dependencies` closure of `apps/mobile` and `apps/electron`; the `@atlastodo/*` core packages are first-party and only walked) has a licence outside its allow-list, which mirrors core's `deny.toml`; `--notices` writes `THIRD_PARTY_NOTICES.txt`, which the release attaches (About → Licenses links to it) and the desktop tarball carries. `scorecard.yml` runs OpenSSF Scorecard on `main` and weekly.
- The audit is `continue-on-error` on purpose. The known unfixable advisories (`braces`, `node-forge`: no patched release yet) are analyzed in `//audit-known` in the root `package.json` — read it before chasing audit findings; fixable advisories go in `overrides`, never an ignore list.
- Branches: work lands on `dev`; `main` is stable-only. Nothing is published without a tag. Cut a pre-release by hand on `dev`: `version:bump X.Y.Z-rc.N`, commit `chore(release): vX.Y.Z-rc.N`, tag, push `dev` and the tag. `main` takes no direct pushes (ruleset "main: PRs only": a PR from `dev`, merge commits only, CI required, no bypass). To ship: on `dev`, `version:bump X.Y.Z` and commit `chore(release): vX.Y.Z`; open a PR `dev` → `main` and merge it; tag the merge commit on `main` `vX.Y.Z` and push the tag; then fast-forward `dev` to `main`.
- Versioning is lockstep within this repo: never hand-edit a version in one manifest. Use `version:bump [--no-notes] [--desktop] <x.y.z|patch|minor|major>` (updates the root and `apps/*` package.jsons, `app.json` (version and the derived versionCode), `bun.lock`, regenerates `nix/bun.nix`, and regenerates `RELEASE_NOTES.md` when the version changes (a stable release lists commits since the last stable tag, so it carries what its rcs did; an rc lists commits since the last tag of any kind); `--no-notes` skips that, `--desktop` also builds the desktop tarball locally). Only `X.Y.Z` and `X.Y.Z-rc.N` are accepted (`patch|minor|major` need a stable current version). The Android `versionCode` is derived, not incremented, by `scripts/version-code.mjs`: `major*1000000 + minor*10000 + patch*100 + slot`, slot = `N` for `-rc.N` (1-98) and 99 for stable, so it rises across rc and stable builds (minor and patch < 100). The Prepare job re-derives it and fails on a mismatch. The core pins are not versions `version:bump` touches.
- A `v*` tag runs `release.yml`: `CI` → `Prepare` (the tag must equal the package.json version and app.json's version/versionCode; extracts the notes; **fails unless all four `ANDROID_*` keystore secrets are set**) → `Android APK + AAB` (signed, permissions check, Play upload when `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` is set), `Desktop tarball`, `Web app tarball` (`atlas-todo-web-X.Y.Z.tar.gz` + `.sha256`, built with `EXPO_PUBLIC_API_URL=/api` for a core server image to pin), `Third-party notices` → `GitHub Release` ("Atlas Todo vX.Y.Z", every file with build provenance attestations and `SHA256SUMS.txt`). Secrets and variables are listed in `apps/mobile/RELEASE.md`. A tag containing `-` is a prerelease: a GitHub prerelease (`--latest=false`), the AAB to the Play **internal** track (`PLAY_STORE_PRERELEASE_TRACK`, default `internal`; stable goes to `vars.PLAY_STORE_TRACK` and internal, one upload), no `atlas-desktop-latest.tar.gz`.
