# Atlas Todo desktop (Electron)

The desktop app for Atlas Todo. It wraps the web export of `apps/mobile` in Electron and adds
native window handling, single-instance enforcement and the OS key store. Data is stored locally
and synced like on every other client.

## Features

- Desktop layout with a persistent sidebar, keyboard shortcuts, a Cmd/Ctrl-K command palette and
  context menus.
- Local storage in Chromium's sandboxed IndexedDB, inside the application profile.
- Single instance: a second launch focuses the running window.
- Window state: size and position are restored, clamped back onto a display that still exists,
  and a maximized session comes back maximized.
- Deep links: `atlastodo://` URLs (for example `atlastodo://task/42`, matching the Expo app's
  scheme) open or focus the app on the linked route. They arrive through the `open-url` event on
  macOS and through argv on Windows and Linux (a cold start's own, or the second launch's via
  `second-instance`). On Linux the installed `.desktop` file must advertise
  `MimeType=x-scheme-handler/atlastodo`, which the packaged flake does.
- Clicking a reminder notification raises the window (the renderer's `Notification.onclick`
  calls the `atlasDesktop.focusWindow` bridge).
- Session keys: the unlocked E2EE keys are wrapped with Electron's `safeStorage` (macOS Keychain,
  Windows DPAPI, Secret Service or KWallet on Linux) instead of a key kept in the browser
  profile. See [Security model](#security-model).
- Tray (Windows and Linux): a tray icon while the app runs, with a menu to restore or quit.
  Closing the window quits the app, unless Settings → Features → "Close to tray" is on. Then it
  hides to the tray and sync and reminders keep running. Ctrl+Q in the window quits outright
  either way, like the tray's Quit. The choice is per install, stored in
  `desktop-settings.json` under Electron's userData, and the toggle only shows where a tray icon
  could be created. macOS keeps its standard close-to-Dock behaviour. The 16x16 monochrome icon
  is generated by `scripts/generate-tray-icon.mjs`.

## Development and usage

### Development mode

This starts the desktop window against the Metro web dev server, with live reload. Dev mode
needs the `--dev` flag, which the scripts below pass, and release builds refuse it.
`ELECTRON_START_URL` overrides the dev server origin (default `http://localhost:8081`).

```sh
# From the repo root via devenv:
desktop:dev

# Or inside apps/electron (needs the Metro web dev server on :8081):
bun run dev
```

### Production mode

This exports the static web bundle and runs Electron against it:

```sh
# From the repo root via devenv:
desktop:start

# Or manually:
cd apps/mobile && bun run export:web
cd apps/electron && bun run start
```

### Packaging

This builds the distribution bundle, copies the web and Electron assets, embeds a self-contained
Nix flake and creates the release tarballs `atlas-desktop-${VERSION}.tar.gz` and
`atlas-desktop-latest.tar.gz`:

```sh
# From the repo root via devenv:
desktop:package

# Or manually:
bash scripts/package-desktop.sh [version]
```

### Release marker

`scripts/package-desktop.sh` writes `dist/release.json` (`{"release": true, "version": "x.y.z"}`)
into the packaged output only, and the tarball's flake installs that `dist/` as is. Its presence
makes `main.js` a release build: `--dev`, `ELECTRON_START_URL` and `ATLAS_DESKTOP_WEB_DIR` are
ignored. `app.isPackaged` cannot make that call, because the Nix package and the tarball run the
stock `electron` binary on `dist/main.js`. A build from `apps/electron` (`bun run build`) never
has the marker.

## Security model

The window runs the web bundle as `app://atlas-todo`. Its `localStorage` holds the session and
the wrapped E2EE keys, so the shell keeps everything else out of that origin.

- Protocol handler: `app://` serves files from the web bundle only. Paths are decoded once and
  checked for containment after resolving (`src/security.ts`, `resolveAppPath`). Anything that
  escapes the bundle, cannot be decoded or carries NUL is a 404. Every response carries a strict
  `Content-Security-Policy` (scripts from the bundle only, no inline and no `eval`) and
  `X-Content-Type-Options: nosniff`.
- Deep links: each `atlastodo://` path segment is decoded and re-encoded. A link whose segment
  decodes to `.` or `..`, or contains `/`, `\` or NUL, is refused. Cold-start links in argv
  (Windows and Linux) are honoured too.
- Navigation: the window only navigates within `app://atlas-todo` (plus the dev server in dev
  mode). Popups are always denied. Other destinations are cancelled, and only `https:`, `http:`
  and `mailto:` links are handed to the OS browser or mail client, never `file:`, `smb:`, `ms-*:`
  or other custom handlers. The same is enforced on the `openExternal` permission. `<webview>` is
  disabled.
- Renderer: `sandbox` and `contextIsolation` are on, there is no Node integration, and the
  same-origin policy applies. The preload exposes only `atlasDesktop.isElectron`,
  `atlasDesktop.focusWindow` and `atlasDesktop.safeStorage`. The main process honours
  `focusWindow` and `safeStorage` only from the main window's top frame while it shows the app.
- Session keys: `atlasDesktop.safeStorage` encrypts or decrypts one byte string with Electron's
  `safeStorage` and nothing else (`src/keyWrap.ts`). The renderer uses it for the session's key
  set (`apps/mobile/src/auth/webKeyStore.ts`). It is used only when `isEncryptionAvailable()` is
  true and, on Linux, the backend is a real keyring (not `basic_text`, which encrypts with a key
  built into Chromium). Otherwise the keys stay wrapped under the browser's WebCrypto key in the
  profile, as in a browser. Keys stored by an older version are opened as before and re-wrapped
  with `safeStorage` on the next launch.
- Plain-http servers: `app://` is a secure origin, so a LAN server on `http://` would be mixed
  content, and `allowRunningInsecureContent` permits it. Electron's dev-mode security warning
  about that is expected. API requests are ordinary CORS requests with
  `Origin: app://atlas-todo`. The server's default (no `CORS_ALLOWED_ORIGINS`) accepts them, and
  a server that sets an allowlist must include `app://atlas-todo`.

### Manual security checklist

Run it against a packaged build (`desktop:package`, then the tarball or flake):

1. Sign in to an `https://` server and to a plain-`http://` LAN server. Sync and the realtime
   indicator ("Live") work on both.
2. Add an attachment, open it in the lightbox and download it. The save dialog appears.
3. Trigger a reminder notification and click it. The window comes forward, also from the tray.
4. Run `xdg-open 'atlastodo://task/<id>'` with the app running and with it closed. Both land on
   the task.
5. Run `xdg-open 'atlastodo://..%2f..%2fDownloads%2fevil.html'`. The app only focuses or opens
   on the start page, and no local file is shown.
6. An external link (About screen) opens in the system browser, and the app window never leaves
   the app.
7. `atlas-desktop --dev` (or with `NODE_ENV=development`) still loads the bundled app, not
   localhost.
8. Sign in, quit from the tray and start again. The app opens unlocked. On Linux, start it once
   with `--password-store=basic`. It asks for the password, because the keyring-wrapped keys do
   not open without the keyring, and it opens unlocked again on the next normal start after
   signing in.

## Release builds and Nix

The `desktop` job in `.github/workflows/release.yml` builds the app on every release tag (`v*`).
The tarball is attached to the GitHub Release as `atlas-desktop-<version>.tar.gz` and as
`atlas-desktop-latest.tar.gz`.

The repository flake ships `atlas-desktop` as a package and as NixOS and Home Manager modules
(`programs.atlas-desktop`). Each release archive also embeds a self-contained desktop flake.

1. Add the flake to your inputs:

   ```nix
   inputs = {
     nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
     atlas-todo = {
       # No nixpkgs follows: it builds with its own pin, the Bun and Node CI tests.
       url = "git+https://github.com/atlastodo/atlas-todo.git";
     };
   };
   ```

   To follow the standalone desktop tarball instead, use
   `url = "tarball+https://github.com/atlastodo/atlas-todo/releases/latest/download/atlas-desktop-latest.tar.gz"`.

2. NixOS module:

   ```nix
   imports = [ inputs.atlas-todo.nixosModules.default ]; # or nixosModules.desktop
   programs.atlas-desktop.enable = true;
   ```

3. Home Manager module:

   ```nix
   imports = [ inputs.atlas-todo.homeManagerModules.default ];
   programs.atlas-desktop.enable = true;
   ```

4. Or install the package directly:

   ```nix
   environment.systemPackages = [ inputs.atlas-todo.packages.${pkgs.system}.atlas-desktop ];
   # or in Home Manager:
   # home.packages = [ inputs.atlas-todo.packages.${pkgs.system}.atlas-desktop ];
   ```

5. Update to the latest release:

   ```sh
   nix flake update atlas-todo
   ```
